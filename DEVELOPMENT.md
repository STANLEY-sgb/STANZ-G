## Project structure (v0.7 — restructured as a real mobile app project)

```
STANZ G GAME/
├─ www/                     the game itself (Capacitor web root)
│  ├─ index.html            single self-contained build — HTML/CSS/JS, no bundler
│  └─ assets/                hero.jpg, academy.jpg, op1–4.jpg (operator portraits)
├─ android/                 native Android project (generated by Capacitor)
│  └─ app/src/main/
│     ├─ assets/public/      a synced copy of www/ — DO NOT edit directly, re-run `cap copy`
│     ├─ res/mipmap-*/       app icon (adaptive + legacy), generated — see tools/gen-icons.py
│     ├─ res/drawable-*/     splash screens, generated
│     └─ AndroidManifest.xml app name, package id, permissions, orientation lock
├─ server/                  Stage 4 online multiplayer server (standalone Node.js + ws)
│  └─ server.js              authoritative room/match logic; serves www/ over HTTP too
├─ tools/
│  └─ gen-icons.py           regenerates every icon + splash PNG from the game's own palette
├─ _reference-not-for-shipping/   quarantined real-person photos — never copy into www/ or android/
├─ capacitor.config.json    appId com.stanzg.game, appName STANZ G, webDir www
├─ package.json             root Capacitor project (core/cli/android)
└─ DEVELOPMENT.md           this file
```

**Why this shape:** `www/` is the one real source of the game — the same files play instantly
as a browser page (the Artifact play link above) *and* get wrapped unmodified into a native
Android app by Capacitor, so there's never two copies of the game logic to keep in sync.
`android/` is a full, ordinary Android Studio project checked in for a developer to open,
build and sign — nothing about it is STANZ-G-specific plumbing, it's the standard Capacitor
template plus our manifest edits and generated art. `server/` is deliberately separate: it's
a backend process, not something bundled into the app, and it can be deployed on its own to
any Node host.

**Turning this into an installable app (what's done vs. what still needs a real machine):**
- ✅ Done here: the Android project is fully scaffolded (Gradle wrapper, manifest, package id
  `com.stanzg.game`, orientation locked to landscape, `INTERNET`/`ACCESS_NETWORK_STATE`
  permissions, `usesCleartextTraffic` for LAN `ws://` multiplayer), and the app icon +
  splash screen are generated from the game's own color palette (`tools/gen-icons.py`).
- ⏳ Needs a machine with the real Android SDK installed (this sandbox only has stale
  `ANDROID_HOME`/`ANDROID_SDK_ROOT` env vars pointing at nothing — no SDK is actually
  present, so no build was attempted here): install **Android Studio**, open the `android/`
  folder, let it sync Gradle, then either run it on a device/emulator directly, or from a
  terminal:
  ```
  cd android
  ./gradlew assembleDebug      # unsigned debug APK, for sideloading/testing
  ./gradlew bundleRelease      # release AAB — needs a signing key before upload
  ```
  A release build must be signed (`keytool` + `signingConfigs` in `android/app/build.gradle`)
  before it can go to the Play Store; that's a one-time step done on whichever machine does
  the actual release.
- Regenerating art after a rebrand: edit the palette constants at the top of
  `tools/gen-icons.py` and re-run `python tools/gen-icons.py` — it rewrites every icon/splash
  density directly under `android/app/src/main/res/`, no network or design tool needed.
- After any change to `www/`, sync it into the native project with `npx cap copy android`
  (or `npm run sync`) before rebuilding — Capacitor does not watch files automatically.

## STAGE 5 — Advanced Graphics, Sound & Optimization ✅ COMPLETE (v0.8, 2026-11-17)

  cycle by default), with sky color, fog color, hemisphere/sun light color and

- **Dynamic weather**: four states (clear/overcast/rain/fog) picked on a weighted
  timer and smoothly blended in over ~12s — rain (1200-point falling particle
  field centered on the player), lowered view distance, occasional lightning
  flashes with delayed thunder (sound travels slower than light), and a real
  gameplay hook: **enemy sight range is reduced in rain/fog**, so bad weather is
  genuinely stealthier, not just prettier. Runs behind the main menu too.
- **Generative music**: a procedural ambient pad (always on, low volume, no
  audio files) that rises into a tenser rhythmic pulse when hostiles are alert
  nearby, the player's been hit recently, or an online match is live — eases
  back down once the danger passes. Muted by the existing sound toggle.
- **Positional audio**: gunfire from AI and other online players now pans
  left/right based on where they are relative to the camera (`StereoPannerNode`,
  falls back to centered mono on browsers without it). Every gunshot now also
  puffs a muzzle-smoke sprite, for free, at the single `muzzleFX()` chokepoint
  every shooter already calls through.
- **Cinematics**: a kill-cam sweeps the camera from the killer's position to the
  fallen player over the first ~1.3s of the death screen (works for AI kills and,
  via a small server protocol addition, online PvP kills too); dying to the
  Battle Royale zone sweeps from a dramatic point on the storm wall instead. A
  slow victory/defeat orbit camera now plays at match end, replacing what used
  to be a frozen frame.
- **Performance pass**: the static world's ~220 collision obstacles are now
  indexed into a spatial grid once at load (`buildObstacleGrid`), so every
  collision push and bullet/sightline check looks up only the handful of
  obstacles in its own 20m cell instead of scanning the whole list — the
  biggest standing CPU cost, hit every frame by the player, every AI soldier,
  and every vehicle, and hit again per sample point on every bullet trace and
  line-of-sight check. Added an automatic graphics-quality downgrade that
  watches sustained low FPS during play and steps the quality down once (never
  back up) if a device is struggling, with a cooldown so it can't thrash.

## First real playtest feedback — connection UX fix ✅ COMPLETE (v0.9.1, 2026-11-17)

The first real person to install the APK got stuck immediately: they opened
the app and landed on the ONLINE MULTIPLAYER screen asking for a server
address they had no way of knowing, and assumed that was required just to
play at all. Three of the four modes never needed that — this was a UI
clarity failure, not a missing feature, plus one real bug this surfaced:

- **Menu now says it outright.** Training/TDM/BR are tagged **NO SETUP**
  (green); Online Multiplayer is tagged **NEEDS A HOST** instead of the old
  generic "NEW". The connect screen itself now opens with a plain-language
  explanation and a way out ("not playing with others right now? tap
  Cancel and pick one of the other three").
- **Fixed a real bug**: `defaultServerUrl()` was pre-filling the address
  field with `ws://localhost:8080` whenever the app ran as the installed
  APK (as opposed to being visited in a browser). That address is
  guaranteed wrong there — it points the phone at itself, not at the host's
  PC — so anyone who left it on the sensible-looking default and hit
  Connect got a silent failure. It now leaves the field honestly blank
  instead of lying with a plausible-looking wrong answer.
- **`server/start-server.bat`**: hosting on Windows is now a double-click,
  no terminal typing — it checks Node.js is installed (with a clear message
  and a link if not), runs `npm install` itself the first time only, then
  starts the server. Verified piece-by-piece against this PC's real
  `cmd.exe` (where node / if-exist / cd-/d all behave as written); a full
  end-to-end double-click run wasn't possible from this sandboxed shell.
- **Server now prints the real LAN address** (via `os.networkInterfaces()`)
  instead of the placeholder text `<this-machine's-IP>` it used to show —
  confirmed on this machine it correctly detects and prints the actual
  address (`192.168.100.179`, in this case) in both the `http://` form to
  read and the exact `ws://` form to paste into the app.
- `HOW_TO_PLAY.md` rewritten to lead with "three modes need nothing, tap
  and play" before anything about hosting.

What this does **not** cover, and needs a decision rather than code: a
*hosted, always-on, works-for-anyone-anywhere* server (so players don't
need to be on the same Wi-Fi, and nobody has to keep a PC running) requires
deploying `server/server.js` to a cloud host with its own account — that's
a real, separate step with its own setup and (usually free-tier, but not
guaranteed-forever) cost, and only the project owner can authorize creating
that account. Flagged to the user as an open question rather than assumed.

Re-verified after every change in this pass: full script still parses via
Node, 0 missing DOM ids, and the 11-check online-multiplayer integration
suite still passes 11/11 against the updated server.

## Asset inventory (all original, generated in code — no external assets)
- Vehicles: procedural jeep/boat meshes (`makeJeep`/`makeBoat` in index.html)
- BR props: cargo plane, parachute canopies, air-drop crates, zone wall — all
  procedural geometry
- Character: procedural mesh rig (`buildCharacter` section of index.html)
- Terrain: procedural heightfield `terrainHeight(x,z)` — single source of truth for
  rendering, physics, and the minimap
- Structures, trees, rocks, clouds: procedural geometry, seeded RNG (seed 90210)
- Sky: procedural day/night gradient + starfield + moon sprite + rain particles
  (Stage 5, `ENV`/`updateDayNight`/`updateWeather` in index.html) — no textures
- Audio: WebAudio-synthesized (noise-based wind/footsteps/thunder, oscillator
  thud, generative ambient+combat music pad — all code, no audio files)
- Fonts: Black Ops One (display), Rajdhani (UI) via Google Fonts
